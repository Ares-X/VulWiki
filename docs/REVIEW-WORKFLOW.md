# 内容维护与验收流程

本流程检查收录资料的保真、展示、资源和检索，不执行文章、HTML 示例、PoC、扫描器或载荷，也不访问示例目标。所有值保持原文；来源已有的占位符不猜补。

## 固定输入与检查范围

开始前记录 Git 提交、工作树状态，以及三个内容根目录下每篇 Markdown 的路径、原始字节数和 SHA-256。分片必须覆盖全部文章且不重叠。任务包同时记录候选条数和唯一文章数；协调者按路径及候选 ID 检查实际输出覆盖，不能凭“完成”声明验收，也不能把文章数当作候选列表的截取数量。审阅阶段不修改文章；审阅者使用相同快照，修改方案另存预览。

报告分别记录全库机器扫描、全文上下文阅读、候选片段阅读与抽查。读取文件计算哈希、运行解析器或匹配正则，均不等于人工全文审阅；不得用一种覆盖代替另一种。技术事实的外部核对和图片像素查看单独记录，未做的仍为未知。

## 运行可重复的检查

在仓库运行已有 Python 检查：

```sh
python -m unittest discover -s tests -v
python scripts/wiki.py check --baseline docs/quality-baseline.json --report /tmp/wiki-quality.json
python scripts/wiki.py build
python scripts/wiki.py build --check
```

渲染检查使用现有博客的 Marked 依赖，无需为内容库安装新依赖。在本地博客检出目录内的 VulWiki 子目录运行：

```sh
node --test tests/render-audit.test.cjs
node scripts/render-audit.cjs --root . --out /tmp/wiki-render-audit
```

独立检出时，可用 `--marked-module` 指向已经安装的 Marked CommonJS 模块；测试同样需要已有 Marked 可被 Node 解析。记录报告中的实际版本，升级解析器时重新检查差异。本工具只对字符串运行 lexer/parser，不将 HTML 加载到 DOM。为保证比较稳定，关闭 Marked 的随机邮箱编码；该结果不能替代浏览器的实际展示检查。

工具输出 `inventory.jsonl`、`candidates.jsonl` 和 `summary.json`，包含完整候选原文、文件 SHA、候选 ID、可定位时的行号和渲染哈希。无法精确定位的嵌套 Markdown 行号为 `null`，不能假设为第一行。输出目录应在仓库之外，保留完整诊断，不脱敏。

Marked 会规范化换行及行首制表符。代码范围检测必须映射回原始位置，不能因 `token.raw` 与原文件不完全相同就把已有围栏中的请求误报为未围栏；原文件仍保留制表符和原始字节。

退出码为零仅代表未命中该工具的结构性阻断。HTTP 边界、HTML 吞入后文、围栏中的标题/图片、表格列数、语言标记、未围栏源码和链接字面量均为待判读候选，包含误报；不能据此声称所有排版和技术内容正确。Python 基线检查同样只表示没有新增债务，原有问题仍在报告中。

## 判读与最小修改

逐项区分旧遗漏、新增回归、原文有意安排与待核。新增回归必须有改动前后的 Git 原文证据，不能仅因本轮才检测到就称为新回归。来源、编号或归档缺损无法确定时保留原文并记录具体疑点。

补丁必须精确绑定当前文件 SHA 和原文跨度。UTF-8 字节偏移、Python 字符位置、JavaScript UTF-16 位置不能互换。建议片段必须在源文中逐字命中；出现错误解码、无法定位、重叠或失效快照时撤回补丁，不能模糊替换。上下文记录不得冒充替换前后文。

只修确认的展示边界；不要统一改写代码、参数、请求字节或解释。HTML 表格后补空行时，保留表格标签、属性、行列、文字和资源值。中性的 `text`/`plain` 围栏允许保留，尤其是有归档缺损说明的示例。

独立的 `<meta>` 标签后紧接未转义的 Markdown 来源引用时，空行缺失也会使引用和链接被当作 HTML 文本。用整篇解析确认后，仅补边界空行；带转义符的归档字面文本不能据此统一解除转义。新增围栏外侧使用真正的空行，含空格的空白行可能使 Marked 的 Setext 标题跨越后续示例。原段落已有行内代码时，不直接外套围栏，以免把格式反引号变成复制出的请求字符。

## 完整结果验收

作者以外的审阅者复核修改预览。新增、移动围栏时，验收整个请求或代码段，而不是只检查已经放入围栏的部分：

- 请求行、全部头部、原有空行和完整请求体必须在正确的代码 token 中。保留原文的尾空格、测试值、作者占位符、反引号和截略；不自动计算或改写 Content-Length。
- 请求后的解释、响应、图片和附件分别检查归属。不能把正文误并入代码，也不能把请求体留在普通段落。
- 完整代码 token 的文本与已确认的 Git 原文跨度逐字比较；仅证明“围栏中的文字没有变”不足以证明范围完整。
- 检查整篇 lexer/parser 结果。HTML 块吞入第一个围栏标记时，后续所有围栏可能错位；只修末尾几个候选会扩大错误。
- 核对元数据、解释、引用、代码值、HTML 表格原文与图片/链接。用精确操作的逆变换验证其余文章字节未改；逆变换只证明改动范围，不能替代内容判读。

修改后对全部文章重跑同一组检查。比较候选增减，确认修正项消失，对新增项重新判读；保留误报与待核的处置及适用文件 SHA，文件或规则变化后不能沿用旧的通过结论。不能把新问题塞进基线使检查变绿。

生成索引后核对全部派生结果、收录/排除关系、目录与本地资源引用。需要构建博客时在隔离目录验证 Markdown 与资源字节进入产物；发布另按已授权范围进行。报告保存实际检查范围、原文证据、最终补丁、撤回建议、通过项和具体未核项。
