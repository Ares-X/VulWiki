## 实际覆盖

三个内容根目录的 5,666 篇 Markdown 全部记录原始 SHA-256，并运行 Marked 4.3.0 的字符串 lexer/parser、Python 质量检查、资源解析及索引对应检查。10 个 `gpt-6-luna` / `low` 子 agent 分别审阅不重叠的 HTML、HTTP、其他格式候选，以及前轮修改保真和本轮补丁预览；所有仓库修改由协调者完成。

候选原文与邻近上下文审阅、整篇机器解析和人工全文阅读分别记在子 agent 报告中。HTTP 审阅覆盖 16 篇全文；不能据此声称人工逐句通读全库，也不能把哈希扫描当作技术事实核验。完整候选 ID、原值、读取范围、修订报告和撤回报告见 [证据目录](reviews/20261003-fifth-polish/README.md)。最终处置以协调者的 `dispositions.jsonl.gz` 为准。

初始工具产生 591 个候选，全部有处置记录。其中 5 项是 Marked 展开行首制表符后导致的代码范围误报；修正工具后，同一原文快照产生 586 项。本轮修正其中 516 项，最终剩余 70 项，新增候选为 0，结构性失败为 0。

| 完整归档 SQL 示例加围栏 | 3 | 原 `=` 行不再被识别为跨段 Setext 标题，值和换行不重写 |
| 解释中的 HTML 标签字面量加行内代码标记 | 2 | Exchange 文章中的 `<details>` 与 `<img src=”x”onerror=”恶意代码”>` 原值不变 |

另外 3 个 SQL 示例和相邻的图片标签来自完整上下文复核，合计 4 处操作不对应初始候选 ID。新增围栏前后使用真正空行，保留围栏内部原有空白。旧 Elasticsearch 请求内被误识别成缩进代码的四个 JSON 片段进入完整请求围栏；整段代码复制文本与 Git 原文跨度逐字比较，而不是要求保留旧的错误分块。

未采用直接外套围栏会把行内反引号变成请求字符的建议。没有解除归档来源行的转义，没有重写代码或说明，没有猜补截断内容，没有任何脱敏，没有补充来源或更改收录状态。

`scripts/render-audit.cjs` 现在将 Marked 规范化后的代码范围映射回原始换行和制表符位置，消除五篇已有围栏请求的误报；新增测试覆盖制表符、CRLF 和围栏外的真实请求。`docs/REVIEW-WORKFLOW.md` 补充该定位要求与来源说明、Setext、行内代码边界的判读方法。
