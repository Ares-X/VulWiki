# VulWiki 内容标准化与修复（2026-10-02）

基线：`41940cb0038d09ca5aaddbe5bffb923e423d210f`。本文仅描述本轮重新实施并重新验证的成果；不沿用此前丢失工作区的测试结果。

## 覆盖与保留规则

- 5,654 篇原始 Markdown 全部保留，增加稳定记录 ID、结构化产品/标题/文档类型、主编号与引用编号角色、来源状态、验证状态、前提与副作用说明。
- 每篇依据已有全文审阅结论逐项校订。能由原文及已核来源确认的错误直接修正；缺版本、出处、必要步骤、截图文本或复现证据的内容明确待核，不补写成已验证事实。
- 不删除原技术方法、请求或操作细节。危险操作补充明确前提、影响和清理提醒；失效或缺失示例保留并标出边界。
- 真实或无法确认性质的凭据只遮罩中段，保留字段名、分隔符和首尾。明确公开默认值、占位符、测试设置值与代码表达式不作机械替换。
- 原文件路径与资源引用保持兼容；部分乱码按原字节可逆恢复，不能恢复的缺文不猜写。

## 去重方式

确认的 85 组同稿/转载关系覆盖 179 份来源文档。通过 `canonical`、`entity_id`、`relation_type: duplicate_of` 统一目录和机器检索入口，所有来源文档仍保留。只凭相同 CVE、产品或接口不合并；互补分析、不同根因、补丁绕过和利用链保持独立。

这代表已确认组的去重，不代表可以证明整个开放文库不存在任何尚未识别的相似稿。机器生成的候选清单仍需人工确认。

## 工程实现

- `scripts/wiki.py`：仅使用 Python 标准库，离线检查元数据、编号角色、来源、资源链接、显示用代码围栏和不可直接渲染的活动 HTML 示例。
- `build`：确定性生成目录、CVE/指纹索引、JSONL 人机共用记录和待核队列；不改源正文，不执行文章代码，不访问文章中的目标。
- `search`：以明确的主编号/引用角色检索，不从整篇提到的 CVE 机械推断主漏洞。
- CI：运行单元测试、拒绝新增质量债、检查生成物一致性；权限仅 `contents: read`。
- `docs/CONTENT-SCHEMA.md`、贡献规范和文章模板定义后续新增内容的约定。
