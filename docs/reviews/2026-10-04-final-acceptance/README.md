# 全库三轮保真与发布前验收（2026-10-04）

本轮基于 PR #11 合并后的 `54ff62213950c7ff86cb8881941844cba5aaeef8`，保持本地 Markdown、Docsify 路由及博客展示层。项目验收是资料保真、对应关系、排版、资源、目录和检索；没有执行文章、HTML 示例、附件、PoC 或扫描器，也没有访问示例目标。未复现不是拒收理由。本轮不补齐缺失来源，不进行任何脱敏。

## 三轮检查范围

1. 固定全部 5844 篇原始 Markdown 的路径、原始字节和 SHA，检查元数据、版本字段、编号角色、指纹、Marked 解析、资源与派生目录。输入有 5064 条既有质量警告、178 个渲染待判读候选；这不是 5844 篇再次逐字人工事实审查。
2. 子任务只提出冻结原文与当前 SHA 绑定的精确方案；按具体归档正文和已有公开资料判读，再由独立审阅者验收。修正元数据时保留旧值为 `previous_*`，保留历史正文、URL、请求字节、代码类型与公开测试值。被撤回或持有的提案、理由及早期报告也保留。
3. 对修正结果重新覆盖全库，验收完整补丁正逆重放、当前资源完整解码、生成器全量投影和检索程序行为。最终新增或改动图片必须实际产生图片 token，解码后的 href 与目标文件/SHA 精确对应；解析未报错不能替代这个检查。

最终精确补丁涉及 **1101 篇、3818 项操作**，每篇都有从基准 Git 原文到当前文件的完整哈希链。各报告分别标明机器载入、全文上下文阅读、片段阅读、来源核对、像素阅读及未核范围；不能将这些不同深度相加后宣称全库技术事实已经确认。

## 实际修正

- 指纹待核字段由 800 项降到 78 项：依据明确的平台原文恢复查询或将历史残片移入旧值字段。已有完整查询保持原值；组合意图、未给出的 AND/OR 和线上平台结果均不猜补。
- 编号角色待核由 212 项降到 24 项。区分主编号、背景引用与不同端点；具体错误映射依 CNA 或维护者资料注明更正，原编号和历史标题保留。版本字段区分实验运行时与影响范围，缺证据时明确未知。
- 静态修正空链接、图片占位、HTML/Markdown 展示边界与说明中的正则字面量；不格式化或补写损坏的源码残片。H2O 的完整正则字符保留为行内代码，已有 Java 代码不变。
- 44 个空 PNG 从同篇历史 Git blob 及旧分类引用恢复，原路径、图像字节和图中值全部保留，并逐张查看像素。部分空文件来自旧 `8c907990` 维护中删除后重新加入为空文件；仅按当前路径历史检索会漏掉迁移前的有效资源。恢复记录不把截图视为本库复现。
- 12 个引用目标实际为 404 HTML，另有一处原始 `![]()` 没有目标，均明确说明原图缺口并完整保留原引用字面。原始 404 文件仍存档。7 个来源当前封面单独注明当前插图、历史图未知及非验证证据，不能冒充历史原图。
- Ivanti 文章恢复 204 个严格 PTCP154/UTF-8 可逆的非 ASCII 乱码片段；归档正文 ASCII 字符流和所有链接/代码字符保持不变。14 行仍不能整行严格恢复，未知片段没有猜补。
- 新增标准库 `resource-audit.py` 及 7 个行为测试，CI 拒绝活动图片引用的缺失、空文件及 HTML 错误页，并保留完整报告。签名检查不代表完整解码；本轮另用已有 Pillow 12.3.0 完整校验当前 6117 张图片及全部 11230 帧，没有解码异常。32 个扩展名与实际容器不符的有效文件保留。

## 本轮拦下的提案问题

独立复核曾拦下跨文章复用 Gitea 说明、对 FortiWeb 误称既有代码缺损、两处空白说明、锐捷查询的尾空格遗漏；它们没有按错误提案写入发布正文。最终全库扫描又拦下本轮新增封面中 6 条含空格的无效 Markdown 图片写法；已按 URI 编码修正并逐项断言实际图片 token/目标 SHA。这是本轮草稿引入并在发布前消除的问题，不能归为原归档缺损。Marked 行内代码的 HTML 实体转义按原始跨度与一次实体解码后的显示/复制字符验收，不能为匹配内部 token 表示改写 `&`。H2O 提案的 31→30 个链接/图片计数未采纳；独立完整实测为 28→27，除错误正则链接外其余 27 个 token 保持一致。
